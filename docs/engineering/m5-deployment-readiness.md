# Inspection deployment readiness

The deployment CLI provides an explicit, pinned **inspection-only** launch and
recovery procedure. It does not install a service, open a firewall, install trust
certificates, start a campaign or qualify a target host. No actual deployment was
performed for this change. Full M5 remains open.

## Prepare private inputs

Use the [owner setup](../guides/dashboard.md#owner-sign-in) to create a password
verifier outside the journal directory. Supply an existing snapshot, server
certificate/private key and trusted CA bundle. The certificate must validate for
the exact origin hostname/IP and have at least 72 hours remaining by default.
Remote binds additionally require a client-certificate CA. These are private
operator inputs, never committed to Git or bundled into journal backups.

Create a private JSON spec with absolute paths (example paths are placeholders):

```json
{
  "version": "dashboard-deployment/1",
  "execution_enabled": false,
  "bind": "127.0.0.1",
  "port": 8443,
  "public_origin": "https://127.0.0.1:8443",
  "state": "C:/fx-private/inspection-state",
  "mode": "NEW",
  "minimum_certificate_hours": 72,
  "files": {
    "snapshot": "C:/fx-private/inputs/snapshot.json",
    "owner": "C:/fx-private/inputs/owner.json",
    "server_cert": "C:/fx-private/tls/server.pem",
    "server_key": "C:/fx-private/tls/server.key",
    "server_ca": "C:/fx-private/tls/ca.pem"
  }
}
```

Unknown fields are rejected. Broker connections/receipts, telemetry, matched-study
journals, simulator controls, external models and alert delivery are deliberately
absent from this profile version. Existing configurable dashboard launches remain
available separately; this profile is not a migration of the current user preview.
Snapshots remain recorded evidence and age normally; launch never refreshes quotes.

## Check and explicitly launch

```powershell
python -m fx_talanta.dashboard.deployment seal --input spec.json --output profile.json
python -m fx_talanta.dashboard.deployment check --input profile.json --output check-001.json
# Explicit operator action; foreground process, no service installation:
python -m fx_talanta.dashboard.deployment run --input profile.json
```

Seal/check open no sockets and create no journal state. An in-memory TLS handshake
checks key/certificate agreement, trusted chain, exact hostname and validity; the
remaining-lifetime policy adds a renewal margin. Client CA parsing does **not** prove
client enrollment, revocation or real remote access. Reports omit paths and secret
contents, but include hashes; keep profiles private because they contain paths.
Outputs refuse overwrite and failures emit a generic message rather than private
validation inputs.

The profile pins artifact bytes and installed package source/assets/migration SQL.
Changes require a reviewed, newly sealed profile. Hashes detect drift; they are not
signatures, a wheel attestation or protection against a compromised local user.
Python/dependency versions and host settings are not pinned by this digest. File
permissions and exclusive control of configuration remain prerequisites: path reads
are checked repeatedly, not an atomic filesystem snapshot. Platform line endings
may require a new seal on another installation. No secrets are generated by sealing.

NEW requires an absent state directory. RESUME requires an existing, healthy SQLite
journal with the same snapshot and compatible disabled external-view bindings.
An incomplete restore fails closed. Launch takes the normal exclusive workspace
lock and uses owner HTTPS sessions; it has no pass-through activation flags. A
preflight PASS does not prove port availability, filesystem write permissions,
exclusive ownership at a future time, DNS reachability or target-host qualification.
The runtime still checks bind/lock failures. A failed launch may leave an empty state
directory; inspect it explicitly rather than automatically resetting or adopting it.

## Stop, backup and restore

Stop the foreground process with Ctrl+C. Normal shutdown closes its listener,
background sampler and SQLite journal and releases the workspace lock. It does not
control a broker terminal. Do not install automatic restart policies around this
command: session expiry and explicit activation boundaries must remain visible.

```powershell
python -m fx_talanta.dashboard.recovery backup --source C:/fx-private/inspection-state --destination C:/fx-private/backup-001
python -m fx_talanta.dashboard.recovery verify --source C:/fx-private/backup-001
python -m fx_talanta.dashboard.recovery restore --source C:/fx-private/backup-001 --destination C:/fx-private/restored-001
```

Backup refuses a workspace owned by a running dashboard. Existing recovery code
copies only allowed journal/calendar/notification evidence and verifies hashes and
SQLite integrity. It excludes owner/TLS/session credentials and external journals.
Backups still contain private evidence and require protected storage.

For restore, create a new spec with `mode: RESUME` and the restored path, retain the
original snapshot, and seal/check again. The restore marker must be
VERIFIED_INSPECTION_ONLY. Owner credentials/certificates must be supplied separately;
old browser cookies and execution/model/operator/delivery authority are not restored.
Use the same RESUME procedure for a normal stopped restart. Certificate renewal and
code updates require a new seal; never overwrite old profiles or reports.

## Acceptance and remaining gates

The deployment tests exercise socket-free preflight, invalid TLS/hostname/lifetime,
unsafe flags, artifact/package drift, mode/binding failures and output preservation.
An actual isolated loopback HTTPS dashboard signs in, rejects operator access,
refuses backup while running, stops, verifies backup, restores and resumes via the
same deployment entry point. Only the blocking server loop is bounded by the test;
the server, TLS, sessions, sampler and SQLite lifecycle are real. Ephemeral fixture
certificates are never installed in a system trust store.

Actual host deployment, real client/recipient acceptance, broker administration and
fault/recovery acceptance, prospective strategy/model runner and qualified inputs
remain open. M1-M3 gaps, B01 REJECT_FOR_PROMOTION, the two-second entry rule and M5's
eight weeks **AND** 100 closed PAPER trades are unchanged.

The [source-hashed Windows acceptance report](../evidence/m5-deployment-readiness-20261106.json)
records **166 backend checks and 10 headless browser scenarios passed**, with zero
skips or flaky results. Broker calls, external model calls and trading remain zero/disabled.
The fixture lifecycle is software evidence, not a production-host deployment report.
